## 📁 Проекты в репозитории

### 1. [Спецификация требований к ПО (SRS) — Passion.ru](./SRS_documentation)
* **Цель:** Разработка полных требований для информационно-развлекательного веб-портала.
* **Что сделано:** 
  * Составлена спецификация по стандарту **RUP SRS (Software Requirements Specification)**.
  * Описаны функциональные сценарии (Use Cases) и требования по модели **FURPS+**.
* **Стек:** `RUP`, `FURPS+`, `draw.io` , `UML`.

### 2. [Проектирование ИС «Салон красоты»](./UML_beauty_salon)
* **Цель:** Моделирование архитектуры и бизнес-процессов системы управления салоном красоты.
* **Что сделано:**
  * Построена диаграмма прецедентов (**Use Case Diagram**) для 4 акторов со связями `include`, `extend`, `generalization`.
  * Разработана логическая модель данных (**Class Diagram**).
  * Проведен сравнительный анализ методологий.
* **Стек:** `UML`, `Use Case`, `Class Diagram`, `Visual Paradigm`

### 3. [Проектирование реляционной БД и запросы(PostgreSQL / PL/pgSQL)](./DB_PostgreSQL)
* **Цель:** Сквозной практический проект по проектированию, нормализации, физической реализации и программированию базы данных.
* **Что сделано:**
  * **Лаб. 1:** Разработаны инфологическая (ER) и даталогическая модели.
  * **Лаб. 2:** Написаны DDL/DML-скрипты с ограничениями целостности (`CHECK`, `FOREIGN KEY`).
  * **Лаб. 3:** Реализованы сложные аналитические запросы с использованием `JOIN`, группировок (`GROUP BY`, `HAVING`) и подзапросов.
  * **Лаб. 4:** Разработана бизнес-логика на уровне СУБД — триггер и хранимая функция на **PL/pgSQL** для автоматической маркировки ключевых событий (`[Key event]`).
